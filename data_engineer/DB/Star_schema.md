# chapter 01. 데이터베이스 이해
## 1. 데이터베이스 개요
### 1.1 데이터
- 데이터 : 현실 세계의 객체(사람, 상품, 장소 등)나 사건(주문, 결제, 방문 등)에 관한 사실을 컴퓨터가 저장하고 처리할 수 있도록 표현한 것
  - 개별적으로 의미가 제한적
  - 목적에 따라 정리되고 연결될 때 분석과 의사 결정에 활용될 수 있음
- 데이터베이스 : 논리적으로 연관된 데이터를 일정한 구조와 규칙에 따라 조직적으로 저장, 관리한 집합
  - 데이터를 효율적으로 저장하고 빠르게 검색하며 정확하게 갱신하고 여러 사용자와 시스템이 공유할 수 있도록 지원함
- 빅데이터 : 데이터의 생성 속도와 형태의 다양성이 급격히 증가하여 기존의 전통적인 데이터베이스 관리 방식만으로는 처리하기 어려운 데이터 환경을 의미
  - 대용량, 고속성, 다양성 특성이 강조됨
  - 기업과 조직은 페타베이트 이상의 데이터를 저장, 분석하기 위해 데이터 웨어하우스뿐 아니라 데이터 레이크와 같은 대규모 저장소 및 분산 처리 기반의 분석 환경을 활용
    - 데이터 웨어하우스(DW) : 정제된 정형 데이터를 저장하고 빠른 비즈니스 보고와 대시보드 분석을 제공하는 중앙 집중식 저장소
      - 데이터 유형 : 주로 표 형태의 정형 데이터만 저장
      - 스키마 방식 : 데이터를 저장하기 전에 구조를 정의하는 쓰기 시 스키마 적용 방식을 씀
      - 주요 목적 : 비즈니스 인텔리전스(BI), 실적 모니터링, 리포트 및 KPI 생성에 최적화되어 있음
      - 사용자 : 비즈니스 분석가, 경영진, 운영팀
      - 서비스 : AWS Redshift, Google BigQuery, snowflake(컬럼지향), MySQL, postgreSQL, Oracle(로우 지향)
    - 데이터 레이크(Data Lake)
      - 다양한 출처에서 수집된 가공되지 않은 원시 데이터를 원래 형식 그대로 보관하는 거대한 저장소
      - 데이터 유형 : 유형, 반정형, 비정형(이미지, 동영상, 로그 등) 모든 데이터를 저장할 수 있음
      - 스키마 방식 : 데이터를 일단 그대로 저장한 뒤 필요할 때 구조를 부여하는 읽기 시 스키마 적용 방식을 사용함
      - 주요 목적 : 데이터 탐색, 머신러닝, 인공지능 모델 훈련을 위한 원천 데이터 보관에 적합함
      - 사용자 : 데이터 과학자와 데이터 엔지니어가 주로 사용
      - 서비스 :
    - 데이터 레이크하우스
      - 데이터 레이크의 저렴한 저장 능력과 데이터 웨어하우스의 트랜잭션(ACID) 관리 및 구조화 기능을 결합한 차세대 아키텍처
     
#### 논외
- 데이터 웨어하우스의 저장 방식 : 로우 지향(Row-oriented)과 컬럼 지향(Column-oriented)올 나뉨
  - 일반적인 서비스용 데이터베이스(RDBMS) : 로우 방식 주로 사용
  - 대용량 분석을 목적으로 하는 데이터 웨어하우스 : 컬럼 지향 방식을 주로 채택

- 로우 지향 (Row-oriented) 방식
  - 개념 : 하나의 레코드(행)에 포함된 모든 컬럼 데이터를 디스크 상에 저장
  - 장점: 특정 사용자의 정보 전체를 가져오거나, 새로운 행을 추가할 때 디스크의 한 곳만 다루면 되므로 매우 빠름
  - 단점: 대량의 데이터 중 "나이(Age)의 평균"을 구하고 싶을 때도 원하지 않는 이름, 주소 등 모든 행의 데이터를 다 읽어야 하므로 불필요한 I/O 비용이 크게 발생
- 컬럼 지향 (Column-oriented) 방식
  - 개념: 동일한 컬럼(열)의 데이터들을 디스크 상에 모아서 저장
  - 장점
    - 대용량 분석 쿼리 시 필요한 컬럼만 골라서 읽을 수 있어 속도가 압도적으로 빠름
    - 같은 데이터 타입이 연속되므로 압축률이 극대화되어 저장 공간과 비용을 크게 아
  - 단점: 새로운 데이터 한 줄(Row)을 추가하려면 각 컬럼별 저장 위치에 분산하여 기록해야 하므로 단일 데이터 입력/수정 작업에는 불리

|구분|로우 지향|컬럼 지향|
|----|--------|----------|
|데이터 저장 방식|행 단위로 데이터를 연속해서 저장|열 단위로 데이터를 연속해서 저장|
|주요 용도|온라인 트랜잭션처리(OLTP)|온라인 분석 처리(OLAP, DW)|
|작업 최적화|데이터 추가(INSERT), 수정(UPDATE)|데이터 조회(SELECT), 집계(SUM,AVG 등)|
|압축 효율|낮음(다양한 데이터 타입이 섞여 잇음)|매우 높음(동일한 데이터 타입이 연속됨)|


#### 가. 데이터
- 데이터 : 컴퓨터 시스템에 저장되고 처리될 수 있도록 표현된 사실을 의미

|구분|정의|대표 예시|저장·관리 형태|분석 난이도|
|----|----|--------|-------------|-------------|
|구조적 데이터|행과 열 구조로 명확하게 정의된 데이터|고객ID, 주문일자, 결제금액, 재고수량, 출결기록|관계형 데이터베이스(RDB), 스프레트 시트, 데이터 웨어하우스|낮음(정형화된 분석 가능)|
|반구조적 데이터|일정한 구조는 있으나 고정된 테이블 형태로 표현되지는 않는 데이터|JSON, XML, 웹/앱 로그, 이벤트 데이터(클릭/뷰), 센서 데이터|NoSQL 데이터베이스, 로그 저장 시스템, 데이터 레이크|중간(구조 변환 필요)|
|비구조적 데이터|고정된 스키마나 테이블 구조로 표현하기 어려운 데이터|문서(PDF/Word), 이미지, 음성, 동영상, 이메일 본문	파일 시스템, 오브젝트 스토리지, 데이터 레이크|높음(정보 추출 및 전처리 필요)|

#### 나. 데이터 VS 정보
- 정보 : 의미와 맥락이 부여되어 해석 가능한 형태로 가공된 데이터를 의미
  - 사용자의 이해를 높이거나 의사결정을 지원하는 데 활용됨
  - 데이터가 특정한 맥락 속에서 해석되거나 요약, 분석되어 이해 가능한 형태로 가공되었을 때 정보가 됨
- 데이터가 정보로 전환되기 위해서는 데이터의 의미, 구조, 사용 맥락이 함께 제공되어야 함

#### 다. 메타 데이터
- 메타 데이터 : 데이터가 실제로 활용되기 위해서는 이 데이터가 무엇을 의미하는지, 어떻게 사용되어야 하는 지를 설명해 주는 정보의 역할을 수행함
  - 데이터의 의미, 구조, 특성, 생성 방식, 사용 맥락 등을 설명하는 데이터
  - 데이터에 대한 데이터로 정의할 수 있음
  - 단순한 설명을 넘어, 데이터의 이해 가능성, 품질 관리, 재사용 가능성을 결정하는 핵심 요소
- 메타 데이터에는 다음과 같은 정보들이 포함됨
  - 데이터 이름(예: 상품코드, 판매일자)
  - 데이터 정의(예: 고객을 구분하기 위해 시스템에서 부여한 내부 식별자)
  - 데이터 유형 및 길이(예: 문자형, 10자리)
  - 허용 값의 범위 또는 규칙(예: 0 이상의 정수, 중복 불가)
  - 데이터 원천(source)(예: CRM 시스템, 웹 로그, 설문조사)
  - 데이터 저장 위치(예: 데이터 웨어하우스, 데이터 레이크, 특정 테이블)
  - 소유권 또는 책임 주체(예: 마케팅팀, 데이터 관리자)
  - 데이터 사용 목적(예: 매출 분석, 고객 세분화, 의사결정 지원)


### 1.2. 파일 처리 시스템
#### 가. 파일 처리 시스템의 개념
- 데이터베이스가 널리 사용되기 전에는 대부분의 정보 시스템이 파일 처리 시스템 중심으로 운영되었음
- 파일 처리 시스템 방식 : 각 부서나 각 응용 프로그램이 자신에게 필요한 데이터를 별도의 파일 형태로 저장하고 관리함
- 파일 처리 시스템의 주요 문제점
  - 데이터 중복
    - 동일한 데이터가 여러 프로그램이나 여러 부서의 파일에 반복 저장될 수 있음
    - 저장 공간 낭비를 초래하고 데이터 수정과 관리의 복잡성을 증가시킴
  - 데이터 불일치
    - 동일한 데이터를 여러 위치에서 각각 수정할 수 있기 때문에 불일치가 자주 발생함
  - 프로그램-데이터 의존성
    - 파일 구조가 조금만 바뀌어도 해당 파일을 사용하는 프로그램을 수정
    - 시스템 유지보수 비용 증가시킴
    - 새로운 기능 추가나 업무 변경에 대한 유연성을 낮춤
  - 데이터 공유의 어려움
    - 조직 전체의 업무 흐름을 통합적으로 파악하기 어려움
    - 협업 과정에서도 비효율이 발생
  - 데이터 접근성의 제한
    - 사용자가 데이터를 직접 자유롭게 조회하기 어려움
    - 정보 요구에 유연하게 대응하기 어려움
  - 유지보수 비용 증가

#### 나. 데이터베이스 접근법
- 파일 처리 시스템의 한계를 극복하기 위해 등장한 개념 : 데이터베이스 접근법
  - 데이터를 개별 프로그램이나 부서의 파일로 관리하는 것이 아니라 조직 전체의 공통 자산으로 보고 통합된 데이터베이스에 저장하여 관리하는 방식
  - DBMS라는 소프트웨어를 통해 데이터베이스에 접근함
    - 데이터 관리의 중심이 프로그램이 아니라 데이터베이스 자체에 위치함

|구분|파일 처리 시스템|데이터베이스 시스템|
|----|---------------|--------------------|
|데이터 관리 방식|프로그램 중심|데이터 중심|
|데이터 저장 구조|부서별 개별 파일|통합 데이터베이스|
|데이터 중복|높음|최소화|
|데이터 일관성|낮음|높음|
|데이터 공유|제한적|조직 전체 공유 가능|
|프로그램 수정 영향|파일 구조 변경 시 프로그램 수정 필요|데이터 독립성 확보|

### 1.3 데이터 베이스
- 데이터베이스 접근법(Database Approach) : 조직 전체 또는 조직의 주요 부서에 걸쳐 데이터를 통합적으로 관리하고 공유하는 방식
- 뷰(View) : 사용자가 필요로 하는 데이터의 일부만을 논리적으로 보여주는 구조
  - 데이터 접근을 제한하고 보안을 유지하는 데에도 중요한 역할
 
#### 가. 데이터베이스 접근법의 장점들
##### 1) 프로그램-데이터 의존성 감소
- 데이터를 사용하는 응용 프로그램과 데이터 구조에 대한 정의가 서로 분리되어 관리됨  => 데이터 독립성
- 데이터 독립성 : 데이터 구조의 변경이 응용 프로그램에 미치는 영향을 최소화할 수 있도록 데이터와 프로그램을 독립적으로 관리하는 개념
- 리포지터리(repository) : 중앙 저장소에 메타데이터 형태로 데이터에 대한 정의와 구조 정보가 관리됨
  - 데이터의 이름, 의미, 속성, 관계, 제약 조건 등 데이터에 대한 다양한 정의 정보가 저장됨
- 데이터가 특정 응용 프로그램에 종속되지 않고 독립적으로 관리됨
  - 시스템 유지보수가 훨씬 수월해짐
  - 새로운 응용 프로그램을 개발하거나 기존 시스템을 확장하는 과정에서도 높은 유연성을 확보

##### 2) 계획된 데이터 중복성
- 중요한 목표 중 하나 : 불필요한 데이터 중복을 최소화하는 것
  - 데이터를 통합적으로 관리하여 동일한 정보가 여러 곳에 반복 저장되는 상황을 줄이도록 설계
- 모든 중복을 완전히 제거하는 것이 항상 가능한 것은 아님
  - 일부 데이터는 관계 표현이나 성능 향상을 위해 제한적으로 중복될 수 있음
    - ex) 주문 테이블에 고객ID를 포함시키는 것은 주문이 어떤 고객에 의해 발생했는지를 나타내기 위한 것으로, 고객 테이블의 주키를 참조하는 외래키 역할
    - 데이터 구조의 의미를 명확히 하고 테이블 간 관계를 표현하기 위한 의도된 중복
  - 중복을 무조건 제거하기보다는 중복의 유형과 범위를 계획적으로 통제하는 것이 중요
    - 데이터 일관성을 유지하면서도 데이터 구조의 효율성과 활용성을 동시에 확보할 수 있음

##### 3) 데이터 일치성 향상
- 중요한 장점 중 하나 : 데이터 일치성(data consistency)을 향상시킬 수 있다는 점

##### 4) 데이터 공유 향상
- 중요한 장점 : 조직 내 여러 사용자와 부서가 동일한 데이터를 공동으로 활용할 수 있다는 점
- 동시 접근 제어(concurrency control) 기능 제공 : 여러 사용자가 동시에 동일한 데이터에 접근하더라도 데이터의 무결성과 일관성이 유지되도록 관리

##### 5) 애플리케이션 개발 생산성 향상
- 새로운 응용 프로그램을 개발하는 데 필요한 시간과 비용을 크게 줄일 수 있음
  - 데이터 관리 기능이 데이터베이스 관리 시스템(DBMS)에 의해 공통적으로 제공되기 때문임
- 데이터의 저장, 조회, 수정, 삭제와 같은 기본적인 데이터 처리 기능이 이미 DBMS에 포함되어 있음
  - 개발자는 데이터 파일 구조나 저장 방식과 같은 기술적인 세부 사항을 직접 구현할 필요 없이, 필요한 데이터를 DBMS를 통해 쉽게 접근하고 활용할 수 있음

##### 6) 데이터 표준 적용 강화
- 조직 전체에 공통적으로 적용할 수 있는 데이터 관리 정책과 표준을 체계적으로 정의하고 적용할 수 있음
- 조직에서는 다음과 같은 다양한 데이터 표준을 정의할 수 있음
  - 데이터 이름 규칙
  - 데이터 형식 및 품질 기준
  - 데이터 접근 권한 관리 규칙
  - 데이터 보안 및 보호 정책
- 데이터의 정의와 구조를 명확하게 하고, 데이터 입력과 활용 과정에서 발생할 수 있는 오류를 줄이는 데 중요한 역할을 함
- 조직 내 여러 시스템과 부서가 동일한 기준을 사용하게 되므로 데이터 공유와 시스템 통합이 보다 원활하게 이루어짐

##### 7) 데이터 품질 향상
- 다양한 관리 기능과 제약 조건을 통해 데이터 품질을 체계적으로 관리하고 향상시킬 수 있음
- 데이터 품질 : 데이터가 정확하고 일관되며 신뢰할 수 있는 상태를 의미
  - 조직의 의사결정과 업무 수행에 중요한 영향을 미침
- 데이터베이스 관리 시스템(DBMS) : 데이터 입력과 저장 과정에서 일정한 규칙을 적용할 수 있도록 무결성 제약(Integrity Constraint) 기능을 제공
  - 무결성 제약 : 데이터베이스에 저장되는 데이터가 반드시 지켜야 하는 규칙
    - ex) 주문 테이블에 주문 데이터를 입력할 때, 해당 주문이 어떤 고객에 의해 이루어진 것인지를 명확히 하기 위해 고객ID가 반드시 존재해야 한다는 규칙을 설정할 수 있음
      - 이러한 규칙이 적용되면 데이터베이스는 존재하지 않는 고객ID로 주문을 입력하는 것을 자동으로 차단하게 됨
    - 데이터 입력 단계에서 오류를 예방하는 역할
    - 잘못된 데이터가 데이터베이스에 저장되는 것을 방지
    - 데이터의 정확성과 신뢰성을 높이고, 데이터 분석이나 업무 처리 과정에서 발생할 수 있는 문제를 줄이는 데 도움을 줌
  - 데이터웨어하우스에서는 운영 시스템에서 수집된 데이터를 분석용 시스템으로 이동시키기 전에 데이터 정제(Data Cleansing) 과정을 수행
    - 중복 데이터 제거, 오류 데이터 수정, 형식 불일치 데이터 정리와 같은 작업이 이루어짐

##### 8) 데이터 접근성 및 반응성 향상
- 프로그램 개발 경험이 많지 않은 최종 사용자라도 자신에게 허용된 권한 범위 내에서 필요한 데이터를 직접 조회할 수 있음
- 데이터 접근 권한 관리와 질의 검증 절차를 함께 운영하는 것이 중요

##### 9) 프로그램 유지 보수 노력의 감소
- 데이터 변경이 시스템 전체에 미치는 영향을 줄일 수 있으며, 결과적으로 프로그램 유지 보수에 필요한 시간과 노력을 크게 감소시킬 수 있음
- 장기적으로 정보 시스템의 운영 비용을 절감하고 시스템의 유연성을 높이는 데 중요한 역할을 함

##### 10) 의사 결정 지원 향상

#### 나. 데이터베이스 요소
- 시스템 개발자 : 새로운 정보 시스템이나 응용 프로그램을 설계하고 구현하는 역할을 담당함
  - 시스템 분석가, 프로그램 개발자 등이 포함됨
  - 시스템 요구사항을 분석하고, 데이터베이스 구조를 설계하며, 응용 프로그램을 개발하는 과정에서 CASE 도구와 다양한 개발 도구를 활용함
- 데이터베이스 관리자(DBA)
  - 데이터베이스의 운영과 관리를 담당하는 전문가
  - 데이터베이스 설계, 보안 관리, 성능 관리, 백업 및 복구 등의 업무를 수행
  - 데이터베이스 환경이 안정적으로 운영되도록 관리함
- 최종 사용자
  - 데이터베이스 시스템을 이용하여 데이터를 입력하거나 조회하고 필요한 정보를 활용하는 조직 구성원을 의미함
  - DBMS와 응용 프로그램을 통해 데이터베이스에 접근하며 업무 수행에 필요한 정보를 얻음
- CASE 도구(CASE: Computer-Aided Software Engineering)
  - 데이터베이스와 응용 프로그램을 설계하고 개발하는 과정에서 사용되는 자동화된 소프트웨어 도구
  - 도구 사용 시, 데이터 모델링, 시스템 설계, 프로그램 구조 설계 등의 작업을 효율적으로 수행할 수 있음
  - 대표적인 기능 : 데이터 모델링(ERD 작성), 데이터 사전 관리, 시스템 설계 지원, 코드 생성 기능 등
- 사용자 인터페이스
  - 사용자와 시스템 사이의 상호작용을 가능하게 하는 요소
  - 메뉴, 화면, 명령어, 버튼 등 다양한 형태로 제공되며 사용자가 데이터베이스 시스템을 쉽게 이용할 수 있도록 도움
- 응용 프로그램
  - 데이터베이스를 활용하여 사용자에게 필요한 기능과 정보를 제공하는 소프트웨어 프로그램
  - 주문 관리 시스템, 고객 관리 시스템, 재고 관리 시스템 등
 
- 리포지터리
  - 데이터 정의, 데이터 관계, 화면 설계, 리포트 양식 등 시스템 개발과 운영에 필요한 정보를 저장하는 중앙 집중식 지식 저장소(knowledge base)
  - 시스템 구성 요소에 대한 메타데이터 관리
  -  데이터베이스 설계와 시스템 개발 과정에서 중요한 역할
  -  테이블 구조, 데이터 타입, 관계 정의, 프로그램 구조 등의 정보
 
- 데이터베이스 관리 시스템(DBMS)
  - 데이터베이스를 생성하고 유지하며 데이터에 대한 접근을 관리하는 소프트웨어
  - 데이터 저장, 검색, 수정, 삭제와 같은 기능 제공
  - 데이터 무결성 유지, 보안 관리, 동시성 제어 등 기능 수행
  - DBMS : Oracle, MySQL, SQL Server, PostgreSQL 등
- 데이터베이스(Database)
  - 논리적으로 관련된 데이터들의 구조화된 집합
  - 조직의 다양한 사용자들이 필요로 하는 정보를 효율적으로 저장하고 관리하기 위해 설계
  - 실제 업무에서 발생하는 데이터 값들 저장

|구분|리포지터리|데이터베이스|

# Chapter 06. 모델링 작업
## 03. EER 다이어그램 모델 설계
### 3.1 스타 스키마 개발
- 스타 스키마(Star Schema) : 팩트 테이블"이 여러 "차원 테이블"에 연결되어 있고, 각 "차원 테이블"이 "팩트 테이블"과 일대일 또는 일대다 관계로 연결됨
  - 팩트 테이블(Fact Table) : 데이터 웨어하우스에서 주로 수치 데이터(측정값)를 저장하는 테이블
    - 비즈니스 활동이나 프로세스의 결과를 나타내는 데이터를 포함됨
    - 판매, 주문, 재고 이동 등의 정량적 데이터를 저장함
    - 외래 키, 측정값(판매 금액, 수량, 비용 등) 등으로 구성됨 => 트랙잭션 데이터
  - 차원 테이블(Dimension Table) : 팩트 테이블의 데이터를 설명하거나 맥락을 제공하는 테이블
    - 분석의 기존 되는 속성 데이터
    - 팩트 테이블의 외래 키와 연결되어 데이터를 분류하거나 필터링하는 데 사용됨
    - 기본 키(PK), 속성(Attributes) 등으로 구성됨 => 마스터 테이터

#### 가. 스키마 개발 전 데이터
- 데이터 분석에 들어가기에 앞서 두 테이블의 공통 키 확인
- 목적에 맞는 조인 방식과 방향을 명확히 정해 테이블을 결합함
- 스키마 개발에서 중요한 역할을 하는 "팩트 테이블"과 "차원 테이블"을 다음과 같이 설정함
  - 팩트 테이블(Fact Table) : 판매 테이블
  - 차원 테이블(Dimension Table) : 고객, 제품 테이블
  -
