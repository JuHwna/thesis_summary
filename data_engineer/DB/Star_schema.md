# chapter 01. 데이터베이스 이해
## 1. 데이터베이스 개요
### 1.1 데이터
- 데이터 : 현실 세계의 객체(사람, 상품, 장소 등)나 사건(주문, 결제, 방문 등)에 관한 사실을 컴퓨터가 저장하고 처리할 수 있도록 표현한 것
  - 개별적으로 의미가 제한적
  - 목적에 따라 정리되고 연결될 때 분석과 의사 결정에 활용될 수 있음
- 데이터베이스 : 논리적으로 연관된 데이터를 일정한 구조와 규칙에 따라 조직적으로 저장, 관리한 집합
  - 데이터를 효율적으로 저장하고 빠르게 검색하며 정확하게 갱신하고 여러 사용자와 시스템이 공유할 수 있도록 지원함
- 빅데이터 : 데이터의 생성 속도와 형태의 다양성이 급격히 증가하여 기존의 전통적인 데이터베이스 관리 방식만으로는 처리하기 어려운 데이터 환경을 의미
  - 대용량, 고속성, 다양성 특성이 강조됨
  - 기업과 조직은 페타베이트 이상의 데이터를 저장, 분석하기 위해 데이터 웨어하우스뿐 아니라 데이터 레이크와 같은 대규모 저장소 및 분산 처리 기반의 분석 환경을 활용
    - 데이터 웨어하우스(DW) : 정제된 정형 데이터를 저장하고 빠른 비즈니스 보고와 대시보드 분석을 제공하는 중앙 집중식 저장소
      - 데이터 유형 : 주로 표 형태의 정형 데이터만 저장
      - 스키마 방식 : 데이터를 저장하기 전에 구조를 정의하는 쓰기 시 스키마 적용 방식을 씀
      - 주요 목적 : 비즈니스 인텔리전스(BI), 실적 모니터링, 리포트 및 KPI 생성에 최적화되어 있음
      - 사용자 : 비즈니스 분석가, 경영진, 운영팀
      - 서비스 : AWS Redshift, Google BigQuery, snowflake(컬럼지향), MySQL, postgreSQL, Oracle(로우 지향)
    - 데이터 레이크(Data Lake)
      - 다양한 출처에서 수집된 가공되지 않은 원시 데이터를 원래 형식 그대로 보관하는 거대한 저장소
      - 데이터 유형 : 유형, 반정형, 비정형(이미지, 동영상, 로그 등) 모든 데이터를 저장할 수 있음
      - 스키마 방식 : 데이터를 일단 그대로 저장한 뒤 필요할 때 구조를 부여하는 읽기 시 스키마 적용 방식을 사용함
      - 주요 목적 : 데이터 탐색, 머신러닝, 인공지능 모델 훈련을 위한 원천 데이터 보관에 적합함
      - 사용자 : 데이터 과학자와 데이터 엔지니어가 주로 사용
      - 서비스 :
    - 데이터 레이크하우스
      - 데이터 레이크의 저렴한 저장 능력과 데이터 웨어하우스의 트랜잭션(ACID) 관리 및 구조화 기능을 결합한 차세대 아키텍처
     
#### 논외
- 데이터 웨어하우스의 저장 방식 : 로우 지향(Row-oriented)과 컬럼 지향(Column-oriented)올 나뉨
  - 일반적인 서비스용 데이터베이스(RDBMS) : 로우 방식 주로 사용
  - 대용량 분석을 목적으로 하는 데이터 웨어하우스 : 컬럼 지향 방식을 주로 채택

- 로우 지향 (Row-oriented) 방식
  - 개념 : 하나의 레코드(행)에 포함된 모든 컬럼 데이터를 디스크 상에 저장
  - 장점: 특정 사용자의 정보 전체를 가져오거나, 새로운 행을 추가할 때 디스크의 한 곳만 다루면 되므로 매우 빠름
  - 단점: 대량의 데이터 중 "나이(Age)의 평균"을 구하고 싶을 때도 원하지 않는 이름, 주소 등 모든 행의 데이터를 다 읽어야 하므로 불필요한 I/O 비용이 크게 발생
- 컬럼 지향 (Column-oriented) 방식
  - 개념: 동일한 컬럼(열)의 데이터들을 디스크 상에 모아서 저장
  - 장점
    - 대용량 분석 쿼리 시 필요한 컬럼만 골라서 읽을 수 있어 속도가 압도적으로 빠름
    - 같은 데이터 타입이 연속되므로 압축률이 극대화되어 저장 공간과 비용을 크게 아
  - 단점: 새로운 데이터 한 줄(Row)을 추가하려면 각 컬럼별 저장 위치에 분산하여 기록해야 하므로 단일 데이터 입력/수정 작업에는 불리

|구분|로우 지향|컬럼 지향|
|----|--------|----------|
|데이터 저장 방식|행 단위로 데이터를 연속해서 저장|열 단위로 데이터를 연속해서 저장|
|주요 용도|온라인 트랜잭션처리(OLTP)|온라인 분석 처리(OLAP, DW)|
|작업 최적화|데이터 추가(INSERT), 수정(UPDATE)|데이터 조회(SELECT), 집계(SUM,AVG 등)|
|압축 효율|낮음(다양한 데이터 타입이 섞여 잇음)|매우 높음(동일한 데이터 타입이 연속됨)|
